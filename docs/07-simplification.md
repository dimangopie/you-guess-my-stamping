# 简化律：一次只说一件事

> 经过三轮叠加（v1 概念 → v2 行为换装 → v3 印章与物理动作），页面堆叠了太多东西。
> 本文是**减法规格**，实现见 `app/base.css` 第 17 节的新零件。

---

## 1. 诊断（实测数据）

| 页面 | 中文字数 | 提示类小字 | 印章数 |
|---|---|---|---|
| me | **1382** | 16 | 6 |
| banks | **994** | **46** | **12** |
| plaza | 651 | 22 | 10 |
| index | 586 | 23 | 3 |
| room | 536 | 29 | 5 |

三个具体病灶：

### 病灶 ① 同一个状态，用整句话说了三遍
```
偏冷 —— 十个人里只有一两个猜得中
落在甜区 —— 十个人玩，五个人左右能猜中
偏直白 —— 几乎人人一猜就中
有点偏甜 —— 再多加两条绕一点的
```
**这是四个文字状态，本该是一条刻度。**

### 病灶 ② 用文字解释 UI
```
① 证件右上角那个孔是打孔机打的 —— 归档过的证件才有孔，补不了
② 背面的《持证须知》滚到底才给签字，签完会盖一枚「已签存档」章
```
UI 需要解释，说明 UI 没做好。**要么改交互，要么用图形/emoji。**

### 病灶 ③ 印章通胀
banks 12 枚、plaza 10 枚 —— 破坏了 v3 自己定的「一章一义」。
**印章多了就不叫状态系统，叫贴纸。**

### 病灶 ④ 重复元素
- **页脚在 5 个页面重复了导航的 4 个链接**（导航在页头已经有了）
- **「来访登记」计数器出现在 3 个页面**（v2 遗留的装饰，无信息量）
- 错误页各有自己的落款，页脚又来一句「本站保留随时调整运行图的权利」

## 2. 五条定律

### 律一 · 一事一表
**一条信息只用一种手段表达。** 用了印章就不再配文字；用了 emoji 就不要再写名词；用了刻度就不要再写形容词。

> 判据：把这条信息的所有表达手段列出来，**如果超过一种，删到只剩最准的那一种**。

### 律二 · 不解释 UI
**需要文字解释的交互，改交互本身。** 实在改不了，用 emoji 提示或用一次性的动效演示，不用常驻文字。

> 「证件右上角那个孔是打孔机打的」→ 删。孔本身就在那儿，**孔的形状已经说明了它是孔**。
> 「滚动到底部才能签字」→ 删文字，改成勾选框旁边的**进度条**（`.gauge`）。

### 律三 · 一章一页
**每页一枚主章。** 其余状态用**颜色 / 形状差异**表达，不再单独刻章。

> 跨页同义同形仍然成立，但同一页里不允许出现 5 枚以上印章。

### 律四 · 页脚不重复导航
页脚只保留一行：**站点标识 + 一句落款**。导航链接已经在页头，删掉。

### 律五 · emoji 优先
**emoji 是这套产品的母语**，它既是内容也是图标。
词库分类、玩家状态、导航项、按钮 —— 能用 emoji 就不用文字。

> 但**克制**：一个界面同时可见的 emoji 图标不超过 6 个，多了就变成噪音。

## 3. 新零件（base.css 第 17 节）

| 零件 | 代替什么 |
|---|---|
| **`.gauge`** 刻度尺 | 「偏冷 / 甜区 / 偏直白」这类文字描述。一条线 + 甜区带 + 指针 + 一个数字 |
| **`.pip`** 状态块 | 整句状态描述。一个色块 + 短语。`.on` 蓝 / `.warm` 琥珀 / `.hot` 红 / `.off` 空 / `.lock` 灰 |
| **`.ico`** emoji 图标 | 文字名词。`.ico` 行内 / `.ico-lg` 大号 / `.ico-solo` 独立 |
| **`.ibtn`** 图标按钮 | 纯文字小按钮（「删除」「展开」「关闭」）→ 一个 emoji |
| **`.say`** | **需要被读到的**说明（正常对比度）。用之前先问：能不能改成交互？ |

同时 **`.hint` 与 `.lbl` 已降级到最浅一档灰** —— 可删的说明就该看起来可删。
真正的信息不应该靠这两个类承载。

## 4. 改写示例（照这个尺度来）

### 例一：状态描述 → 刻度
```html
<!-- 改前：一句话 -->
<div class="note">落在甜区 —— 十个人玩，五个人左右能猜中</div>

<!-- 改后：一条刻度，文字全删 -->
<span class="gauge">
  <span class="track">
    <i class="band" style="left:40%;right:40%"></i>
    <i class="pin" style="left:52%"></i>
  </span>
  <b class="val">52%</b>
</span>
```

### 例二：解释 UI → 删 / 换图形
```html
<!-- 改前 -->
<div class="hint">① 证件右上角那个孔是打孔机打的 —— 归档过的证件才有孔，补不了</div>

<!-- 改后：整句删除。孔自己会说话。 -->
```

### 例三：文字按钮 → 图标按钮
```html
<!-- 改前 -->
<button class="btn sm ghost">删除这件作品</button>

<!-- 改后 -->
<button class="ibtn" title="注销这件作品">🗑</button>
```

### 例四：三态文字 → 状态块
```html
<!-- 改前 -->
<span>当前状态 · 未签字</span>
<span>当前状态 · 已勾选，待签字</span>
<span>当前状态 · 已签字 2025.10.04</span>

<!-- 改后：一个 pip + 日期，状态靠颜色说 -->
<span class="pip lock">未签</span>
<span class="pip warm">待签</span>
<span class="pip on">已签 · 2025.10.04</span>
```

### 例五：词库分类 → emoji + 短名
```html
<!-- 改前 -->
<div class="cat-name">成语俗语</div>
<div class="cat-desc">四字成语 · 俗语 · 歇后语</div>

<!-- 改后：emoji 承担"是什么"，短名承担"叫什麼"，描述删掉 -->
<div class="cat"><i class="ico-lg">🀄</i>成语俗语</div>
```

## 5. 量化目标

| 指标 | 现状 | 目标 |
|---|---|---|
| 单页中文字数 | 最高 1382 | 见下表 |
| 提示类小字 | 最高 46 | **≤ 12** |
| 单页**装饰性**印章 | 最高 12 | **≤ 4** |
| 页脚导航链接 | 5 页重复 | **0**（只留落款）|

### 字数目标（按页型）

| 页型 | 页面 | 目标 |
|---|---|---|
| 落地页 | index | ≤ 320 |
| 工具页 | plaza / room / works / banks | ≤ 550 |
| 登录 | login | ≤ 280 |
| 错误页 | 404 / 500 / offline / full | ≤ 220 |
| **主页** | **me** | **≤ 1150** |

### ⚠ 主页为什么是 1150

**《持证须知》12 条正文 = 727 字，它是内容，不是说明。**
「条款一个字不删」+「整页 ≤ 600」在数学上不可能成立（727 > 600）。

**修正的是目标，不是页面。** 除须知正文外，me 的其余全部只有 371 字 —— 那部分已经够精简了。

> 这条修正本身就是律一的推论：**要求应该服从材料的性质，而不是让材料去迁就一个好看的数字。**
> 把条款塞进 JS 动态渲染来让静态计数腰斩，是**骗计数**，明令禁止。

### 印章计数的口径

**只数装饰性印章。** 以下**不计入**上限（它们是功能件或材质件，不是"又盖了一个章"）：

- 钢印（`.stamp.steel`）—— 它是证件的物理压印
- 归档孔、装订孔（`.hole` / `.bind`）—— 物理动作的痕迹
- 签字章（`.stamp`「已签存档」）—— 它是一个交互的结果
- 角标小印（如头像上表示件数的那枚）—— 它是按钮
- **逐条状态章**（列表里每一项各盖一枚，如公告的「封存 / 已揭晓」）——
  它是**那一条的**状态，不是对同一件事的重复强调。
  按"章形种类"计（3 种），不按"可见实例"计（13 枚）。

超出上限的，是那些**对同一件事反复强调而盖的章** ——
例如同一个「甜区」既盖圆章又写小字又标红。

> **口径一句话：数的是「同一件事被说了几遍」，不是「页面上有几枚章」。**

**注意：不是把所有文字删光。** 机构感靠的正是单据上的字 —— 但那些字是**内容**（编号、日期、金额、条款），不是**说明**。
删的是说明，留的是内容。这个区分是这次简化里唯一需要判断力的地方。

> **判据：这行字是"单据上本来就有的"，还是"设计者加来解释的"？**
> 前者留，后者删。
