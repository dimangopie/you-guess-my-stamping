# 参考设计：《破烂艺术家》的「一处替换承接两个冲突」

来源：[手游那点事专访](http://www.nadianshi.com/2026/08/417676) ·
截图存于 [refs/scrap-artist](refs/scrap-artist/README.md)

## 用户的原话（这条是本项目的设计原则）

> 在游戏房间中，绘制和观赏他人绘画的交互逻辑是不变的。
> 在破烂艺术家中，绘制和观赏时交互逻辑只有两个不同点：
> **能否交流**（会画的人不能透露信息，所以不能交流，但可以看别人交流并点赞）、
> **能否修改画布**。
>
> 破烂艺术家用**一个修改承接两个逻辑冲突**，
> 将交流区域中的**发表言论替换为素材区**。
> **一次修改，承接多个冲突。** 我认为这是非常优秀的设计，你要参考这个逻辑。

## 拆解

多数人会怎么做：**做两套界面** —— 一套「绘制模式」，一套「观赏模式」，
各自摆放面板、各自维护状态。代价是两套界面会慢慢长歪。

《破烂艺术家》的做法：**界面只有一套**。

    同一块侧栏
    ├── 上面的交流记录      —— 两个模式**完全相同**
    └── 底部的输入槽        —— 两个模式**唯一的差异点**
            观赏态 → 「发表言论」       （画布只读：你改不了）
            绘制态 → **素材区**         （画布可改；且不能发言 —— 一说话就泄底）

**一处替换，同时承接了两个冲突**：

| 冲突 | 由这一处替换如何解决 |
|---|---|
| 能否交流 | 槽里是素材区时，就没有发言入口 |
| 能否修改画布 | 槽里是素材区时，画布才可改 —— 两者由**同一个状态**驱动，不可能不同步 |

**关键不在"换了什么"，而在"只换一处"** —— 因为两个冲突本来就同源：
*能改画布的人，就是不能说话的人*。所以它们该由**一个**开关驱动，
而不是两个各自维护的布尔值。

## 我们怎么落地（房间页）

`.flow-slot`（新增）就是那个槽。`paintSlot()` 是唯一的开关：

    function paintSlot(){
      const d = drawer();
      const isMe = d && d.n === ME;          // 轮到我画 = 绘制态
      canvas.classList.toggle("view-only", !isMe);
      if(isMe)  slot.innerHTML = 素材区;      // 分类 tab + emoji 网格
      else      slot.innerHTML = 发表言论;    // input + 发送 + 👍 点赞
    }

- **素材数据与拼图台同一套**（`LIB`），不是抄一份
- 画布不是两套 —— **同一个画布**挂 `.view-only` 类
- `paintSlot()` 挂在 `paintTurn()` 里，跟着回合推进自动切

## 这条原则能推广到本项目其它地方

| 场景 | 当前做法 | 按这条原则 |
|---|---|---|
| 绘制 / 观赏 | ~~两套界面~~ 已合并 | ✅ 一处替换 |
| 游戏中 / 结算 | `hits>0` 时展开玩家列表 | 可考虑：结算时**左栏**从素材区换成玩家列表（同样是"换一处"） |
| 拼图台 vs 房间 | 两个页面，**且应当保持两个** | 见下 |

## 更正：拼图台不是「房间的绘制态」

我一度把拼图台写成「永远处于绘制态的房间」——**这是错的**。用户澄清：

> 拼图台还是要保留下来的，因为它可以用来搞搞**自己创作**放在**个人的作品集**中。

两者是**不同的产品**，只是共用交互零件：

| | 房间 | 拼图台 |
|---|---|---|
| 人数 | 多人 · 轮流出题 | **单人** |
| 节奏 | 有时限、有回合 | **没有时限，慢慢做** |
| 交流 | 有（猜测流 + 点赞） | **没有** |
| 产出 | 一局结束，翻篇 | **进个人作品集，长期留存** |
| 出口 | — | 封存**入册** → 归档票根册 |

**所以那条「一处替换」原则只适用于房间**（房间内部才有绘制/观赏两种模式）。
拼图台只有一种模式，本来就不需要替换。

共用的是**零件**：同一套 `LIB` 素材、同一个画布、同一套 `.pc` 物理。
共用零件 ≠ 合并页面 —— 这一点我之前混了。


## 反例：我之前的做法

我在同一件事上犯过至少三次同样的错 —— **给两个同源的冲突各配一个开关**：

1. `.bench` 有 6 条互相冲突的 `grid-template-columns`（改了没删旧的）
2. 画布尺寸在两页各写一套（399 vs 427）
3. `.col` 的 padding 在拼图台修了、房间漏了

**共同点**：同一个决定散在多处，于是必然不同步。
《破烂艺术家》这条原则的普适形式是：

> **同源的冲突，由一个开关驱动；一处替换，胜过两处分别维护。**
